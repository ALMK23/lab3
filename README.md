# Согласование переводов

REST API для совместной работы над переводами. Владелец проекта (редактор) загружает исходный текст по сегментам,
переводчики переводят сегменты, а редактор утверждает переводы или отклоняет их с замечаниями.

## Сущности

- **Пользователь** — участник: имя, email.
- **Проект перевода** — название, целевой язык, владелец, статус (`DRAFT`, `IN_PROGRESS`, `REVIEW`, `COMPLETED`, `ARCHIVED`).
- **Исходный сегмент** — часть текста проекта и её порядковый номер.
- **Перевод сегмента** — автор, текст, статус (`DRAFT`, `SUBMITTED`, `APPROVED`, `REJECTED`).
- **Замечание редактора** — замечание к переводу, статус (`OPEN`, `RESOLVED`, `REJECTED`).

Проект состоит из сегментов, у сегмента может быть несколько переводов, у перевода — замечания.
Для всех сущностей есть CRUD.

## Бизнес-операции

1. **Запуск проекта** — владелец переводит проект в работу, если в нём есть сегменты.
2. **Отправка перевода на проверку** — автор отправляет перевод, если по нему нет открытых замечаний
   и у сегмента ещё нет другого перевода на проверке или утверждённого.
3. **Отклонение перевода** — редактор отклоняет перевод и оставляет замечание.
4. **Устранение замечания** — автор закрывает замечание и исправляет текст перевода.
5. **Утверждение перевода** — редактор утверждает перевод без открытых замечаний; когда утверждены все сегменты,
   проект переходит на финальную проверку.
6. **Снятие замечания** — редактор снимает неактуальное замечание.
7. **Завершение проекта** — владелец завершает проект, если все сегменты утверждены.
8. **Архивирование** — завершённый проект отправляется в архив и больше не меняется.
